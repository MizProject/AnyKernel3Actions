## 1. Overview

`AnyKernel3Actions` is a modular, zero-dependency **Python 3.9+ standard-library** GitHub Composite Action suite for packaging compiled Android/Linux kernels using [`osm0sis/AnyKernel3`](https://github.com/osm0sis/AnyKernel3) as base.

Key capabilities:
- Clones `osm0sis/AnyKernel3` with `--no-tags` (or copies a local directory) and strips `.git`, git tags, `.github`, `.git*` metadata, and `README.md` while keeping `LICENSE`.
- Discovers and stages compiled kernel images (`Image*`, `zImage*`), DTBs (`dtb` concatenation or prebuilt `dtb`/`dtbo`/`dt`/`recovery_dtbo`/`system_dlkm`/`vendor_dlkm`), `.ko` kernel modules, `ramdisk/`, `vendor_ramdisk/`, `patch/`, `vendor_patch/`, `banner`, and `version`.
- Extracts Linux version strings from `kernel.release`, `utsrelease.h`, or compressed/raw binaries (`raw`, `gzip`, `xz`/`lzma`, `bz2`, pure-Python `lz4`).
- Includes a **[Beta]** `discover` autodetect scour component checking `cwd` -> indexed kernel source tree (`Makefile` + `arch/`, `out/` then `arch/`) -> GitHub Actions `artifacts/` directories, confirming every candidate via binary magic + embedded Linux strings.
- Configures and validates `anykernel.sh` properties, shell variables (`BLOCK`, `IS_SLOT_DEVICE` for `boot_a`/`boot_b`, `RAMDISK_COMPRESSION`, `PATCH_VBMETA_FLAG`, etc.), `dump_write`/`split_flash`/`keep` install modes, optional `@Chainfire` SCSI `deepsleep-fix`, and multi-partition blocks.
- Packages clean flashable `.zip` archives with Unix `0755` permissions on `update-binary` and `tools/*`, SHA-256/MD5 checksums, and GitHub Step Summaries.

## 3. Utilizing Features

### 3.1 Root Action vs Modular Sub-Actions

- **All-in-one (`action.yaml`)**: Runs `prepare` -> `process-kernel` -> `configure` -> `package` automatically.
- **Individual sub-actions (`components/*/action.yaml`)**: Chain `components/prepare` -> optional `components/discover` -> `components/process-kernel` -> `components/configure` -> `components/package` when custom build/inspection steps are needed between stages.

### 3.2 Critical Configuration Rules (Avoid Common Pitfalls)

1. **`block` requires a full boot partition path (never bare `boot` for target device builds)**:
   - Always point `block` to the device's full block node without `_a`/`_b` slot suffix:
     - Qualcomm: `/dev/block/bootdevice/by-name/boot` or `/dev/block/platform/soc/<addr>/by-name/boot`
     - Samsung / Exynos / MediaTek / generic: `/dev/block/by-name/boot` or `/dev/block/platform/<controller>/by-name/boot`
     - Generic multi-device zips only: `auto`
   - Leaving upstream Galaxy Nexus `omap_hsmmc.0` raises `ValueError`. Bare short names (e.g. `boot`) emit a warning and fail when `strict: "true"`.
2. **`is-slot-device` controls A/B `boot_a` / `boot_b` resolution**:
   - `"1"`: A/B slot devices (`boot_a` / `boot_b`). Keep `block` without `_a`/`_b`. Setting `_a`/`_b` in `block` alongside `is-slot-device` `"1"` or `"auto"` fails validation to avoid `boot_a_a`.
   - `"0"`: Non-A/B single-slot devices (`boot`).
   - `"auto"`: Dynamically resolves `boot_a`/`boot_b` on A/B devices and `boot` on non-A/B devices.
3. **`install-mode` for ramdisk vs `init_boot` devices**:
   - `"dump_write"` (default for upstream `anykernel.sh`): Uses `dump_boot;` ... `write_boot;`. Strips Galaxy Nexus `tuna` sample edits when `strip-example-patches` is true.
   - `"split_flash"`: Uses `split_boot;` ... `flash_boot;` and appends `flash_generic` for staged `vendor_dlkm`, `system_dlkm`, and `dtbo`. Required when `boot` has no ramdisk (e.g. Android 13+ `init_boot` GKI devices).
   - `"keep"`: Preserves custom `anykernel.sh` install bodies while still allowing property/variable overrides and optional command injection.
4. **Optional `deepsleep-fix`**:
   - Setting `deepsleep-fix: "true"` (or `--deepsleep-fix true`) injects `@Chainfire`'s SCSI `write_protect` / `cache_type` (`echo 'temporary none'`) loop immediately after `dump_boot;` / `split_boot;` (and before `ramdisk-patch-commands` and `write_boot;` / `flash_boot;`), guarded by `2>/dev/null` and the `# Deepsleep fix (@Chainfire)` deduplication marker.
5. **[Beta] Autodetect & Kernel Verification**:
   - Opt in via `autodetect: "true"`, `artifacts-dir: <path>`, or `components/discover`.
   - Scour order: `cwd` (`cwd`, `cwd/out`, `cwd/arch/*/boot`) -> indexed workspace kernel source (`Makefile` + `arch/`, checking `<ksrc>/out`, `<workspace>/out`, then `<ksrc>/arch/*/boot` if `out/` absent) -> `artifacts-dir` / common `artifacts`/`dist`/`output` dirs / `$RUNNER_TEMP` / bounded workspace scour.
   - Every candidate must pass `inspect_kernel_binary()` (header magic + decompressed payload Linux version banner & kernel `.rodata` strings). Never blindly accepts stub/text/ELF/corrupt files.

### 3.3 CLI Subcommands (`main.py`)

*(LLM Maintenance Note: Update this list if subcommands or key flags change in `ak3_actions/cli.py`.)*

- `python3 main.py prepare` — clone/copy AnyKernel3 base and strip `.git` tags/metadata.
- `python3 main.py discover` — **[Beta]** scour workspace/`out/`/`arch/`/artifacts and output verified paths.
- `python3 main.py process-kernel` — stage kernel image, DTB/DTBO/DLKM, modules, ramdisk/patch, banner/version.
- `python3 main.py configure` — configure properties, shell vars, `deepsleep-fix`, install mode, extra partitions, and run `sh -n`.
- `python3 main.py package` — build zip archive (excluding `.git`, `.github`, `README.md`, `*placeholder`), compute SHA-256/MD5, and append `$GITHUB_STEP_SUMMARY`.
- `python3 main.py build` — run the full pipeline in one command.

### 3.4 Template Variables & Config Precedence

- **Template placeholders**: `{kernel_version}`, `{kernel_image}`, `{kernel_string}`, `{device}`, `{devices}`, `{date}`, `{datetime}`, `{sha}`, `{short_sha}`, `{ak_base_version}`.
- **Config files (`config-file`)**: Supports `.json`, `.toml` (Python 3.11+), `.properties`/`.conf`/`.env`, and `.yml`/`.yaml` (only if PyYAML is installed). Key aliases (`kernel.string`, `kernel-string`, `kernel_string`, `BLOCK`, `block`, `deepsleep.fix`, `deepsleep_fix`, `deepsleep-fix`, etc.) normalize via `canonicalize_config_dict()` in `ak3_actions/config.py`.
- **Override precedence**: `CLI flags > INPUT_* environment variables > config-file > existing anykernel.sh values`.

## 4. Architecture & Contributing Rules

1. **Zero external runtime dependencies**: `ak3_actions/` MUST run using only the Python 3.9+ standard library (`dependencies = []` in `pyproject.toml`). Never require third-party packages like `pyyaml` at action runtime (`test_actions_metadata.py` skips gracefully when PyYAML is absent).
2. **GitHub Actions injection prevention**: NEVER interpolate `${{ inputs.* }}` directly inside bash `run:` scripts in `action.yaml` or `components/*/action.yaml`. Always bind inputs via `env: INPUT_<NAME>: ${{ inputs.<name> }}` and read via `get_env_input()` / `get_env_raw()`. `tests/test_actions_metadata.py` enforces this rule automatically.
3. **Inter-step state stays outside `staging_dir`**: Persist cross-step metadata in `state_file_for_staging(staging_dir)` (`.<name>.ak3-state.json` in `staging_dir.parent`), never inside `staging_dir`, so `staging_dir` stays a clean AnyKernel3 tree even when `create-zip: false`.
4. **`anykernel.sh` shell constraints**:
   - Values inside `properties() { ' ... '; }` must NOT contain single quotes `'` or newlines.
   - `NO_BLOCK_DISPLAY`, `NO_MAGISK_CHECK`, and `NO_VBMETA_PARTITION_PATCH` are tested with `[ ! "$VAR" ]` by `ak3-core.sh`, so disabling them MUST delete/omit the variable rather than emitting `=0;`.
   - Primary boot shell variable edits MUST stay above the first `reset_ak` so secondary partitions (`init_boot`, `vendor_kernel_boot`, `vendor_boot`) are untouched.
   - Generated `anykernel.sh` must pass `sh -n` and use LF (`\n`) endings.
5. **No logic duplication**: Keep shared payload decompression in `ak3_actions/kernel.py` (`_extract_inner_payload`), shared config normalization in `ak3_actions/config.py` (`canonicalize_config_dict`), and shared CLI/pipeline kernel arg extraction in `ak3_actions/cli.py` + `ak3_actions/pipeline.py`.
